# המילטון עיצוב — אתר דמו

אתר סטטי (HTML/CSS/JS בלבד, ללא build step) לעסק רהיטים פיקטיבי "המילטון עיצוב".
כולל טופס יצירת קשר המחובר ל-n8n, כפתור וואטסאפ צף, ופאנל ניהול תוכן אמיתי המגובה ב-Supabase.

## מבנה הפרויקט

```
hamilton-design/
├── index.html      דף האתר (עוגנים לכל הסקשנים)
├── style.css        כל העיצוב
├── script.js        רינדור תוכן, טופס יצירת קשר, פאנל ניהול + Supabase
├── setup.sql         סקריפט הקמת מסד הנתונים ב-Supabase
└── README.md
```

## 1. הקמת מסד הנתונים (Supabase)

1. היכנסו לפרויקט ה-Supabase שלכם (כבר מוגדר בקוד: `ufqciiyrbwfagnhtnumv`).
2. בתפריט הצד: **SQL Editor → New query**.
3. הדביקו את כל תוכן הקובץ [`setup.sql`](setup.sql) והריצו (Run).
4. זה ייצור את טבלת `site_content`, יגדיר את מדיניות ה-RLS (קריאה פתוחה לכולם, כתיבה רק למאומתים), ויכניס שורות תוכן ברירת מחדל.

## 2. יצירת משתמש מנהל

יצירת המשתמש מתבצעת ב-Dashboard ולא ב-SQL (Supabase מנהל את טבלת ה-auth בעצמו):

1. **Authentication → Users → Add user**.
2. הזינו אימייל וסיסמה עבור המנהל.
3. סמנו **Auto Confirm User** (כדי שלא יידרש אימות מייל).
4. שמרו — עם הפרטים האלה תתחברו בכפתור "כניסת מנהל" שבתחתית האתר.

> אפשר להוסיף כמה משתמשי מנהל שרוצים, לכל אחד עם ה-email/password שלו.

## 3. הדבקת מספר הוואטסאפ

בקובץ [`script.js`](script.js), בשורה הראשונה של קטע ה-CONFIG:

```js
const WHATSAPP_NUMBER = "PASTE_PHONE_NUMBER_HERE";
```

הכניסו את המספר בפורמט בינלאומי, ללא `+` וללא `00`. לדוגמה, מספר ישראלי `050-1234567` הופך ל־`972501234567`.

## 4. חיבור ל-n8n

טופס יצירת הקשר כבר שולח `POST` בפורמט JSON ל-webhook הקיים:

```js
const N8N_WEBHOOK_URL = "https://n8n-production-3818.up.railway.app/webhook/df88f21d-6a5b-4a72-bc00-bf236b8af24c";
```

הגוף הנשלח כולל את כל שדות הטופס (`name`, `phone`, `email`, `message`) ושדה `timestamp`. אין צורך בפעולה נוספת — רק לוודא שה-webhook הזה עדיין פעיל ב-n8n.

## 5. איך פאנל הניהול עובד

- כפתור קטן "כניסת מנהל" נמצא בפוטר האתר.
- לחיצה עליו פותחת מודל התחברות (`supabase.auth.signInWithPassword`).
- לאחר התחברות מוצג פאנל צד (Sidebar) שמאפשר לערוך:
  - כותרת הראשי וסלוגן ה-Hero
  - כותרת וטקסט האודות
  - צבעי התימה (ראשי/משני) עם color picker
  - כל פרטי המוצרים (שם, מחיר, תיאור, ותמונה — הדבקת קישור **או** העלאת קובץ ישירות מהמחשב)
- כל שמירה שולחת `upsert` לטבלת `site_content` ב-Supabase, ומיד גם מעדכנת את מה שמוצג בעמוד עצמו.
- בכל טעינה של האתר (לכל מבקר, לא רק למנהל) נשלפים הערכים העדכניים מ-Supabase. אם החיבור נכשל מכל סיבה — מוצג תוכן ברירת המחדל שכתוב בקוד (`DEFAULT_CONTENT` ב-`script.js`), כך שהאתר אף פעם לא "נשבר".

### העלאת תמונות מוצר

לכל מוצר בפאנל הניהול יש שני שדות לתמונה:
1. **קישור לתמונה** — הדבקת URL ישיר (מ-Unsplash, מהאתר שלכם וכו').
2. **העלאת קובץ מהמחשב** — בחירת קובץ תמונה מהמחשב מעלה אותו ל-Supabase Storage (bucket בשם `product-images`, שנוצר אוטומטית ב-`setup.sql`) ומעדכנת את שדה הקישור בעצמה לכתובת הציבורית של הקובץ שהועלה. עדיין צריך ללחוץ **"שמירת מוצרים"** אחרי ההעלאה כדי שהשינוי יישמר בפועל ויוצג לכל המבקרים.

### הוספת/הסרת מוצרים

עריכת פאנל הניהול תומכת בעריכת 8 המוצרים הקיימים. כדי להוסיף או להסיר מוצר, ערכו ישירות את המערך `products` בשורה המתאימה בטבלת `site_content` (עמודת `value`) דרך Supabase Table Editor, או הרחיבו את `renderAdminProducts()` ב-`script.js` בהתאם לצורך.

## 6. העלאה ל-GitHub Pages

1. צרו repository חדש ב-GitHub והעלו אליו את כל תוכן התיקייה (`index.html`, `style.css`, `script.js`).
2. ב-repository: **Settings → Pages**.
3. תחת **Source** בחרו את ה-branch הראשי (`main`) והתיקייה `/ (root)`.
4. שמרו — האתר יעלה לכתובת `https://<username>.github.io/<repo-name>/` תוך דקה-שתיים.

### חלופה: Netlify

גררו את תיקיית הפרויקט ישירות ל-[app.netlify.com/drop](https://app.netlify.com/drop), או חברו את ה-repository מ-GitHub דרך "Add new site → Import an existing project".

## הערות טכניות

- אין תלות ב-npm/build — כל הקבצים סטטיים לחלוטין, כולל ה-SDK של Supabase שנטען מ-CDN.
- תמונות המוצרים, ה-Hero והאודות נטענות מ-[images.unsplash.com](https://unsplash.com) עם ID קבוע לכל תמונה, נבחר כך שיתאים לסוג הרהיט שהוא מייצג (ספה, שולחן אוכל, כורסה וכו'). תמונות האווטארים בהמלצות עדיין מ-[picsum.photos](https://picsum.photos) (אלה רק דיוקנאות placeholder, לא תלויות תוכן). בכל שלב אפשר להחליף לתמונות מוצר אמיתיות — פשוט להחליף את כתובות ה-`image` בטבלת `site_content` (או ב-`script.js` לתוכן ברירת המחדל).
- מפתח ה-`anon key` של Supabase מיועד לשימוש בצד לקוח (ציבורי) — זה בטוח כל עוד מדיניות ה-RLS מוגדרת נכון (כפי שמוגדר ב-`setup.sql`).
